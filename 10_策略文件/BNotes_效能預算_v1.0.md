# BNotes 效能預算 v1.0（2026-11-26 定版）

本文件是 BNotes 的效能合約：任何新頁面、新文章、新功能上線前，先對照本預算。超出預算不是「之後再優化」，而是上線前先修。

## 一、圖片

| 項目 | 規格 | 上限 |
|---|---|---|
| Hero 圖 | WebP，寬 ≤1408px，quality 80（管線：`05_Scripts/compress-images.py`） | ≤300 KB |
| 文內圖 | WebP，寬 ≤1200px，quality 80 | ≤200 KB |
| 格式 | 一律 WebP（OG 圖可另備 JPG 版本供社群平台相容） | — |
| 載入 | 首屏主視覺 + 第一列卡片可 `eager`；其餘一律 `loading="lazy"` + `width/height` 屬性（防 CLS） | — |

背景：2026-11-26 校正前，全站 112 張圖中位數約 1.4MB（JPEG 原圖直上），首頁 eager 載入高達 37MB。校正後首頁 eager 降至約 4.3MB（結構面：去重 + lazy 化）；圖片本體待 binary 發布通道開通後，以已備妥的 WebP bundle 一次換裝（預估再降至約 1MB 級距），此後新圖一律走管線，不再回到原圖直上。

## 二、頁面重量

| 頁面 | 預算 |
|---|---|
| 首頁 | HTML ≤150KB（未壓縮）；eager 總量 ≤1.5MB（換裝 WebP 後） |
| 文章頁 | HTML ≤120KB；hero 之外圖片全 lazy |
| 分類頁 | 卡片圖全 lazy |

## 三、第三方腳本

- 分析：GA4（gtag）+ Cloudflare Web Analytics 為現行組合；新增任何第三方腳本（廣告、社群外掛）須先評估重量與隱私影響，並記錄於本文件修訂紀錄。
- 廣告（未來）：版位固定尺寸預留、延遲載入，廣告 payload 不得阻塞 LCP；規格見《BNotes_廣告位與事件規格_v1.0》。

## 四、量測節奏

- 每月一次：以 Stanley 的 Mac Chrome 拉 GA4/GSC（口徑見運營 runbook），Core Web Vitals 欄位一併記錄，與基線對照。
- 每次大改版後：重測首頁 + 一篇代表性文章的頁面重量（本文件第二節口徑）。
